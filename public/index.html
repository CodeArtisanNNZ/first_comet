START HERE · 2 MINUTES

What is a project?

A software project is a folder of files that work together to solve one problem. A simple website may contain only three files. Bigger applications add a server and a database when they actually need them.

Example: a student portfolioindex.html holds the contentstyles.css controls how it looksapp.js adds interaction
01FrontendWhat people see and click
02BackendPrivate logic on a server · optional
03DatabaseSaved information · optional
04HostingA computer that keeps it online
!
Do not learn everything before starting.

For your first website, begin with HTML, CSS and a little JavaScript. Add a backend only when you need private logic, accounts or secure operations. Add a database only when information must remain after the page closes.

THE SHORTEST CORRECT PATH

From empty folder to live website

Open each step in order. Every step tells you what to understand, what to do and when you are finished.

1
Decide one useful resultBefore writing code
⌄

Understand: A project is not a list of every feature you can imagine. It is one problem and one useful result.

Do: Complete this sentence: “I am building ___ for ___ so they can ___.” Then list only three features for version one.

Finished when: You can explain the project in two sentences without technical words.

2
Create the folder and filesSet up your workspace
⌄

Understand: VS Code edits files. A browser displays the website. They are different tools.

Do: Create a folder, open it in VS Code, then create index.html, styles.css and app.js. Connect the CSS and JavaScript files from the HTML.

Finished when: Opening index.html in the browser shows your heading and style.

3
Build one complete screenHTML → CSS → JavaScript
⌄

Understand: HTML gives structure, CSS controls presentation, and JavaScript changes what happens after an action.

Do: Build the navigation, main content and one working interaction. Check it on a narrow phone-sized window.

Finished when: A new user can use the main feature without your explanation.

4
Save versions with GitCreate safe checkpoints
⌄

Understand: Git tracks versions on your computer. GitHub stores a remote copy and helps people collaborate.

git initgit add .git commit -m "Build first working version"

Finished when: git status says the working tree is clean after your commit.

5
Put the code on GitHubConnect the remote repository
⌄

Understand: A repository is the project and its Git history. A push sends your local commits to GitHub.

Do: Create an empty GitHub repository, copy its setup commands, connect it as origin, then push the main branch.

Finished when: Refreshing GitHub shows your files and latest commit. Never upload passwords or .env files.

6
Choose hosting and deployMake it available online
⌄

Static HTML/CSS/JS: GitHub Pages or Cloudflare Pages.

React/Next.js frontend: Vercel or Cloudflare.

Backend server: A service that supports your runtime, such as Render, Railway or a cloud provider.

Do: Connect the GitHub repository, confirm the build settings, deploy, and open the generated URL.

Finished when: The live URL works in a private browser window and on a phone.

7
Add data, a domain and safetyOnly when the project needs them
⌄

Database: Use it for accounts, posts, orders or anything that must be saved. Supabase provides hosted PostgreSQL; learn tables, rows, relationships and access rules before storing real user data.

Domain: Buy or obtain a domain, add it inside the hosting dashboard, then follow the exact DNS records it provides.

Safety: Keep secrets in environment variables, validate input, enable access rules and test errors.

Finished when: Refreshing keeps saved data, the domain uses HTTPS and private data is not publicly readable.

BEGINNER SCHOOL

Learn how a project actually works

No complicated definitions. Start with what each part does, then learn only the tools you need to build it.

THE BIG PICTURE

A website is usually three parts working together.

Think of an online shop: the frontend is the shop customers see, the backend is the worker handling requests, and the database is where the shop keeps its information.

1FrontendWhat people see
→
2BackendWhat handles the work
↔
3DatabaseWhat remembers data
01
FRONTEND

The part people see and touch

Buttons, text, pictures, menus, forms and page layouts are frontend. If a person can see it or click it in the browser, it is usually part of the frontend.

Learn these in this order
  1. HTMLBuilds the structure: headings, buttons, forms, images.
  2. CSSMakes it look good: colours, spacing, layout and mobile design.
  3. JavaScriptMakes it react: clicks, menus, forms and changing content.
  4. Responsive designMakes the same page work on phones and laptops.
EXAMPLEHTML = button · CSS = blue button · JS = what happens when clicked
02
BACKEND

The part working behind the screen

The backend receives a request, checks what should happen, talks to the database and sends an answer back. Users normally do not see this code.

Learn these in this order
  1. Requests & responsesUnderstand how the browser asks a server for something.
  2. APIsLearn the simple rules frontend and backend use to talk.
  3. One backend languageStart with JavaScript/Node.js or Python. You do not need both.
  4. Validation & logicCheck input and decide what your app is allowed to do.
  5. Authentication & secretsLearn sign-in, permissions and environment variables.
EXAMPLE“Log me in” → backend checks account → sends success or error
03
DATABASE

The place your app remembers things

A database stores information so it is still there later: users, products, messages, orders, lessons, appointments or anything else your project needs to remember.

Learn these in this order
  1. Tables, rows & columnsLearn how information is organised.
  2. SQL queriesStart with SELECT, INSERT, UPDATE and DELETE.
  3. IDs & relationshipsLearn how one table connects to another.
  4. Rules & permissionsDecide who is allowed to read or change each record.
  5. PostgreSQL / SupabaseUse a real database service after the basics make sense.

BEGINNER ORDER

What should I learn first?

Do not try to master everything before starting. Learn enough for the next small thing you are building.

  1. 1HTMLMake a basic page
  2. 2CSSMake it readable and responsive
  3. 3JavaScriptAdd simple behaviour
  4. 4API + backendMake the page talk to logic
  5. 5SQL + databaseSave and retrieve real data
  6. 6Auth + deployProtect it and put it online
