START HERE · 2 MINUTES

What is a project?

A software project is a folder of files that work together to solve one problem. A simple website may contain only three files. Bigger applications add a server and a database when they actually need them.

Example: a student portfolioindex.html holds the contentstyles.css controls how it looksapp.js adds interaction
01FrontendWhat people see and click
02BackendPrivate logic on a server · optional
03DatabaseSaved information · optional
04HostingA computer that keeps it online
!
Do not learn everything before starting.

For your first website, begin with HTML, CSS and a little JavaScript. Add a backend only when you need private logic, accounts or secure operations. Add a database only when information must remain after the page closes.

THE SHORTEST CORRECT PATH

From empty folder to live website

Open each step in order. Every step tells you what to understand, what to do and when you are finished.

1
Decide one useful resultBefore writing code
⌄

Understand: A project is not a list of every feature you can imagine. It is one problem and one useful result.

Do: Complete this sentence: “I am building ___ for ___ so they can ___.” Then list only three features for version one.

Finished when: You can explain the project in two sentences without technical words.

2
Create the folder and filesSet up your workspace
⌄

Understand: VS Code edits files. A browser displays the website. They are different tools.

Do: Create a folder, open it in VS Code, then create index.html, styles.css and app.js. Connect the CSS and JavaScript files from the HTML.

Finished when: Opening index.html in the browser shows your heading and style.

3
Build one complete screenHTML → CSS → JavaScript
⌄

Understand: HTML gives structure, CSS controls presentation, and JavaScript changes what happens after an action.

Do: Build the navigation, main content and one working interaction. Check it on a narrow phone-sized window.

Finished when: A new user can use the main feature without your explanation.

4
Save versions with GitCreate safe checkpoints
⌄

Understand: Git tracks versions on your computer. GitHub stores a remote copy and helps people collaborate.

git initgit add .git commit -m "Build first working version"

Finished when: git status says the working tree is clean after your commit.

5
Put the code on GitHubConnect the remote repository
⌄

Understand: A repository is the project and its Git history. A push sends your local commits to GitHub.

Do: Create an empty GitHub repository, copy its setup commands, connect it as origin, then push the main branch.

Finished when: Refreshing GitHub shows your files and latest commit. Never upload passwords or .env files.

6
Choose hosting and deployMake it available online
⌄

Static HTML/CSS/JS: GitHub Pages or Cloudflare Pages.

React/Next.js frontend: Vercel or Cloudflare.

Backend server: A service that supports your runtime, such as Render, Railway or a cloud provider.

Do: Connect the GitHub repository, confirm the build settings, deploy, and open the generated URL.

Finished when: The live URL works in a private browser window and on a phone.

7
Add data, a domain and safetyOnly when the project needs them
⌄

Database: Use it for accounts, posts, orders or anything that must be saved. Supabase provides hosted PostgreSQL; learn tables, rows, relationships and access rules before storing real user data.

Domain: Buy or obtain a domain, add it inside the hosting dashboard, then follow the exact DNS records it provides.

Safety: Keep secrets in environment variables, validate input, enable access rules and test errors.

Finished when: Refreshing keeps saved data, the domain uses HTTPS and private data is not publicly readable.

WHAT DOES LOCALHOST MEAN?

Your computer temporarily becomes the server.

Normally a website lives on a server connected to the internet. With localhost, the server is running on your own computer. Your browser opens the site from your machine instead of from the public internet.

LOCALHOSTYou → your computer → website
ONLINE WEBSITEYou → internet → public server → website
LOCALHOST HAS LIMITS

Not public. Other people cannot normally open your localhost link.

Your computer must run it. Close the local server and the site stops.

No real domain yet. You use an address such as localhost:5500.

Online behaviour can differ. Domains, HTTPS, secrets and hosting rules are tested again before launch.

02
MILESTONE 02

Build the page structure with HTML

AFTER 01

Now you may start building the actual webpage. HTML tells the browser what each piece of content is.

YOU MUST UNDERSTAND

Headings for titles · paragraphs for text · links for navigation · images for visuals · buttons for actions · forms for user input · sections for page structure.

SUCCESS MEANS

You can build a simple page with a heading, text, image, link, button and form, and it works on localhost.

Then you are eligible for Milestone 03.
03
MILESTONE 03

Make the page look right with CSS

AFTER 02

CSS controls how the HTML looks. Keep testing every change on localhost.

YOU MUST UNDERSTAND

Colours · fonts · spacing · width and height · Flexbox · Grid · responsive design for phones and laptops.

SUCCESS MEANS

Your page is readable, aligned and usable on both a laptop-sized screen and a phone-sized screen.

Then you are eligible for Milestone 04.
04
MILESTONE 04

Add behaviour with JavaScript

AFTER 03

JavaScript makes the page react. A button can open something, a form can be checked and content can change without reloading the whole page.

YOU MUST UNDERSTAND

Variables · functions · conditions · events · finding HTML elements · changing text/classes · basic form handling.

SUCCESS MEANS

You can make at least one useful interaction work correctly on localhost without copying a complete solution blindly.

Then your first frontend is ready for Milestone 05.
05
MILESTONE 05

Connect a backend

AFTER FRONTEND

The backend handles work the browser should not do by itself: checking requests, applying rules, protecting secrets and talking to a database.

YOU MUST UNDERSTAND

Request → response · API routes · JSON · one backend language such as Node.js or Python · validation · environment variables.

SUCCESS MEANS

Your localhost frontend can send a request to your localhost backend and display the answer.

Then you are eligible for Milestone 06.
06
MILESTONE 06

Make the project remember with a database

AFTER BACKEND

A database keeps information after the page closes: accounts, projects, products, messages, orders or any other information your app must remember.

YOU MUST UNDERSTAND

Tables · rows · columns · IDs · relationships · SELECT · INSERT · UPDATE · DELETE · permissions. Then use PostgreSQL, Supabase or another suitable database.

SUCCESS MEANS

Your app can save one real record, reload the page and retrieve that same record safely.

Then you are eligible to prepare the project for the internet.
07
MILESTONE 07

Preview online, then publish

FINAL STEP

Even when the project will live on GitHub, Vercel or Cloudflare, keep a local copy. Make changes locally first, check the result, then push or deploy the version that worked.

1Edit locallyChange your files on your computer.
→
2Test localhostCheck layout, buttons, forms and errors.
→
3Push / deploySend the tested version online.
→
4Test the live URLCheck again because hosting can behave differently.
Teacher rule: a successful localhost build is not the final product, but an unsuccessful localhost build should never be your production deployment.
